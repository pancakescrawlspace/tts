# TTS pilot for audiobooks: log

A test of the three models picked in [tts-survey-2026-11.md](tts-survey-2026-11.md)
against this repo's Kokoro setup, with audiobooks as the goal. Run on 2026-11-23 on
an Apple M3 Max (48 GB unified memory, macOS 27.2.1).

| Engine | Checkpoint | Voice |
|---|---|---|
| Kokoro (baseline) | `hexgrad/Kokoro-82M` (repo's `.venv`) | `am_onyx` |
| Phonon 31M | `gradium/phonon-31m-en` | preset `us_russell` (can't clone, see step 3) |
| VoxCPM2 | `mlx-community/VoxCPM2-bf16` | cloned from the reference |
| Fish Audio Drama 3 | `mlx-community/fish-audio-drama-3-4bit` | cloned from the reference |

Later in the day, VoxCPM2 (and for Dutch also Drama 3) was also tried with two real
voices: Jay Dyer's (personal use) and the user's own, recorded in Dutch. See step 7.

## Summary

| Run | Speed | Peak memory | WER | 3+ word errors | Clone similarity | Voice consistency (mean / min) | Words/min |
|---|---|---|---|---|---|---|---|
| Kokoro `am_onyx` | 10.1x | (PyTorch) | 0.67% | 0 | (it *is* the reference voice) | 0.933 / 0.706 | 204 |
| Phonon `us_russell` | **14.7x** | 3.6 GB | 0.96% | 0 | n/a (preset voice) | 0.857 / 0.577 | 201 |
| VoxCPM2, `am_onyx` clone | 2.1x | 9.9 GB | 0.48% | 0 | 0.758 | 0.925 / 0.762 | 186 |
| Drama 3, `am_onyx` clone | 1.6x | 28.6 GB | **0.32%** | 0 | **0.804** | 0.907 / 0.770 | 153 |
| VoxCPM2, Jay Dyer clone | 2.0x | 10.0 GB | 0.91% | 0 | 0.762 | 0.864 / 0.656 | 158 |

Each run is the same 3,755 words of 1 Clement (about 18–24 minutes of audio). The
columns are explained in step 5.

- **All four engines are accurate enough for audiobooks.** None skipped, repeated or
  invented a passage. WER is below 1% everywhere, and most of what's left is the
  recognisers stumbling on archaic words and names.
- **Speed sets them apart.** At these speeds the whole book (66 minutes at Kokoro's pace)
  takes about:
  - **Phonon:** 5 minutes
  - **Kokoro:** 7 minutes
  - **VoxCPM2:** 35 minutes
  - **Drama 3:** just under an hour, because it also reads 25% slower, so there is more audio to make
- **Phonon is the cheap upgrade.** It's faster than Kokoro and as accurate, but it can't
  clone, and its voice varies more from section to section than any other run (lowest
  consistency score).
- **Drama 3 clones best** (closest to the reference) and is the most accurate. It reads
  slowly (153 wpm against Kokoro's 204) and needs 29 GB of memory. Its licence forbids
  cloning a real person without their consent.
- **VoxCPM2 is the practical cloner:** Apache 2.0, 10 GB, 2x realtime, and it speaks Dutch.
- **Real voices are harder to clone than a synthetic one.** The Jay Dyer clone is less
  steady than the `am_onyx` clone made by the same model.
- **Listening is the deciding test.** These numbers rule out broken output, but they don't
  measure how natural or pleasant the narration sounds. See *Listening guide* at the end.

## 1. Environment: `.venv-mlx`

All three models run through [mlx-audio](https://github.com/Blaizzy/mlx-audio), natively
on Apple Silicon, so one venv covers them. It is a third venv next to `.venv` (Piper,
Kokoro) and `.venv-coqui`, because mlx-audio pulls in transformers 5.24.

- Python 3.11.6 (python.org), mlx-audio 0.6.7, mlx 0.32.4. Pinned in `requirements-mlx.txt`.
- The same certifi `sitecustomize.py` as the other venvs, because this Python has no CA bundle.
- Phonon isn't a separate model type in mlx-audio. It loads through the `pocket_tts`
  implementation (`gradium_phonon_tts` → `pocket_tts`).

Downloads:

| Repo | Size | Note |
|---|---|---|
| `gradium/phonon-31m-en` | 0.22 GB | Apache 2.0 |
| `mlx-community/VoxCPM2-bf16` | 4.96 GB | Unquantised, so quality isn't limited by quantisation |
| `mlx-community/fish-audio-drama-3-4bit` | 23.8 GB | The 8-bit build is 42 GB, too much next to everything else in 48 GB |
| `mlx-community/whisper-large-v3-turbo` | 1.6 GB | For the checks. Its tokenizer files are missing; they come from `openai/whisper-large-v3-turbo` (JSON only). |
| `mlx-community/parakeet-tdt-0.6b-v3` | 2.5 GB | Second recogniser for the checks |
| `aufklarer/SpeechBrain-ECAPA-VoxCeleb-20M-MLX` | small | Speaker embeddings for the checks |

huggingface_hub 2.x keeps the large files in a shared store,
`~/.cache/huggingface/blobs/`. The per-repo folders under `hub/` only hold links, so
`du` on them shows a few hundred KB. Free disk space went from 293 GiB to 252 GiB,
models plus the pilot's audio (1.0 GB in `out/pilot/`: section WAVs and joined copies).

## 3. One voice for every engine

To compare the engines rather than voices, every engine that can clone reads in the
same voice: Kokoro's `am_onyx`, the voice of the existing audiobook. The reference clip
(`ref_onyx.wav`, 8.56 s, 24 kHz) is Kokoro reading the first two sentences of chapter 20,
which isn't in the test text. Because it's a synthetic voice, cloning it raises no
consent question.

**Phonon can't clone.** The open checkpoint leaves out the speaker encoder:

```
ValueError: This checkpoint omits the speaker encoder; use a bundled voice embedding.
```

Gradium publishes 102 ready-made voice embeddings instead (`gradium/phonon-voices`,
Apache 2.0). New voices are made in Gradium's hosted Studio. `tools/phonon_voices.py`
rendered the reference sentence with Phonon's default voice and the 12 English male
voices, and ranked them by ECAPA speaker similarity to `ref_onyx.wav`:

|---|---|---|---|---|
| uk_spencer | 0.284 | | us_easton | 0.206 |
| uk_hugh | 0.269 | | uk_toby | 0.197 |
| uk_teddy | 0.267 | | us_preston | 0.178 |
| default | 0.263 | | us_trevor | 0.173 |
| uk_alfie | 0.236 | | uk_edwin | 0.161 |
| **us_russell** | **0.234** | | us_miles | 0.131 |
| | | | us_micah | 0.051 |

None of them is close (the same speaker typically scores above 0.6), so this ranking
says little. `us_russell` is the best-scoring US voice, in line with the audiobook's
brief (American, male, lower pitch). All 13 samples are in `out/pilot/phonon_voices/`.

**VoxCPM2: which cloning mode.** mlx-audio's VoxCPM2 ignores `ref_text`. It offers
`ref_audio` (audio only), `prompt_audio` + `prompt_text` (the reference as a continuation
prompt, which matches the model card's "ultimate cloning"), or both. A test on the title,
greeting and chapter 1 (1.6 min):

| Mode | Speed | WER | Clone similarity | Voice consistency (mean / min) | Loudness spread |
|---|---|---|---|---|---|
| `ref` | 1.50x | 0.68% | 0.688 | 0.924 / 0.889 | 1.55 dB |
| **`prompt`** | 1.62x | 0.34% | **0.759** | 0.930 / 0.865 | 0.36 dB |
| `both` | 1.56x | 0.34% | 0.754 | 0.923 / 0.839 | 0.25 dB |

These WERs come from the early Whisper-only check (step 5), but every mode got the same
treatment, so the comparison holds. `prompt` was chosen: it gives the closest clone at
the same accuracy.

**Drama 3** takes `ref_audio` plus `ref_text`.

## 4. Rendering: `tools/pilot_render.py`

This is the MLX counterpart of `tools/render.py`, with the same text clean-up and layout:
the heading and the body of each section are rendered separately, with 0.5 s of silence
after each. Every engine uses the same random seed (0) and default sampling, at speed 1.0.

How each engine handles long text:

- **Phonon** splits a section into sentences itself.
- **Drama 3** splits it itself into chunks of about 300 bytes. Each chunk is generated with
  the first and the previous chunk as context, which is meant to keep the voice steady
  over long text.
- **VoxCPM2** doesn't split at all. The script cuts the body into chunks of at most 300
  characters at sentence ends, then at `;`/`:`, then at commas. Each chunk is followed by
  0.25 s of silence, as Kokoro's are.

Output is one 16-bit WAV per section at the engine's own sample rate (Kokoro and Phonon
24 kHz, Drama 3 44.1 kHz, VoxCPM2 48 kHz). Timing and peak memory per section go to
`timings.jsonl`. The Kokoro baseline was rendered with the repo's own `tools/render.py`,
and its timings were taken from that script's progress output.

## 5. Checks: `tools/pilot_check.py`

The checks target what goes wrong in audiobooks:

1. **Skipped, repeated or invented words.** The audio is transcribed by two different
   speech recognisers, and each transcript is aligned word by word with the source.
   - **WER** (word error rate): per section, the lower of the two recognisers' error
     rates. That makes it an upper bound on what the TTS got wrong.
   - **3+ word errors:** runs of three or more words that differ from the source, after
     the rules below.
2. **Voice drift.** An ECAPA speaker embedding is taken per 6 s window. "Clone
   similarity" compares each window with the reference clip. "Voice consistency" compares
   it with the run's own average voice, which shows whether the voice stays the same all
   the way through. The lowest-scoring windows are listed so they can be found and
   listened to.
3. **Speed, peak memory, loudness spread between sections, clipping, words per minute.**

### Getting a recogniser that can be trusted

It took two rounds to get recogniser checks whose errors mean something. The test case
was the Kokoro baseline: `tools/check.py` had already proven that Kokoro speaks every
word, so any "missing" text there is a recogniser error.

**Round 1: Whisper alone.**

| Whisper setup | Kokoro WER | 3+ word errors | What went wrong |
|---|---|---|---|
| Default long-form transcription | 14.95% | 5 | Whole chapter bodies missing. After "Chapter N." and its pause, Whisper skips ahead a full 30 s window. |
| Cut at pauses into pieces under 28 s | 10.67% | 6 | Still stops after "Chapter N." (with timestamps on, even inside one window), and makes up a sentence for a near-silent piece ("now I'll leave the table for five seconds") |
| + timestamps off, near-silent pieces skipped | 3.21% | 1 | A 27 s piece came back as only its last sentence |
| + pieces under 15 s | 1.02% | 0 | |

That looked solved, but on the Phonon and Jay Dyer runs Whisper reported 8 and 18
missing passages (WER 9.3% and 14.4%). Those engines had spoken every one of them:
their audio was as long as expected, and the surrounding text carried on as it should.
Whisper was still cutting some 12–13 s pieces short ("Chapter 1." for 13 s of speech;
"Jealousy..." for a whole sentence).

**Round 2: two recognisers.** Parakeet TDT 0.6B v3 is a different kind of model, and
it transcribed those same sections almost word for word. But given one whole 102 s
section, Parakeet in turn dropped the last sentence, which Whisper had heard fine.

Each recogniser loses text in its own way, while text that the TTS really skipped is
missing for both. So the final rule (Parakeet in pieces of at most 30 s, Whisper in
pieces of at most 15 s):

- **Dropped or replaced text** counts only when *both* transcripts have a 3+ word
  difference at the same spot. An early version also counted a two-word spelling
  difference ("round about" / "roundabout") as agreement, which produced one false
  alarm. That was removed.
- **Added text** (repeats, made-up words, fillers) counts from Parakeet alone. Whisper
  tidies its transcripts: it dropped the Jay Dyer clone's "uh" and, in the self-test
  below, a whole repeated phrase.

**Self-test.** A copy of the Kokoro run was given two faults on purpose: 4 s cut out of
chapter 4 (30–34 s) and 4 s repeated in chapter 9 (16–20 s played twice). The final
check reports exactly those two: the deleted passage ("unto thee shall he turn and thou
shalt rule over him and Cain said unto Abel his brother...") and the inserted repeat
("…our eyes on them that ministered perfectly unto His excellent glory, let us set").
Nothing else was flagged.

With this, Kokoro's WER is 0.67%: what's left is names (Abiram → "Abaram"),
"countryman" → "countrymen", and the like. That's the floor to compare against.

## 6. Results: 1 Clement

The final numbers are in the *Summary* table at the top. Details per engine:

**Kokoro (baseline).** 0.67% WER, nothing skipped. Its "clone similarity" (0.905) only
shows what an exact match scores, since Kokoro made the reference. 4 clipped samples.

**Phonon 31M (`us_russell`).**
- The fastest by far: 18.3 minutes of audio in 1.2 minutes, using 3.6 GB.
- 0.96% WER, nothing skipped. The only 3+ word difference was "along lived" heard as
  "a long live", which the final rule no longer counts.
- Its voice is the least steady: consistency 0.857 on average, 0.577 at worst. The
  lowest windows are in chapter 16 (the longest section) and chapter 65.

**VoxCPM2 (`am_onyx` clone, prompt mode).**
- 2.1x realtime, 9.9 GB. 0.48% WER, nothing skipped.
- Clone similarity 0.758. Voice consistency 0.925, about the same as Kokoro's own 0.933.
- It reads a little slower than the reference voice (186 against 204 wpm).

**Fish Audio Drama 3 (`am_onyx` clone, 4-bit).**
- 1.6x realtime, 28.6 GB. The most accurate run: 0.32% WER, nothing skipped.
- The closest clone: similarity 0.804.
- It reads much more slowly: 153 wpm, so 24.0 minutes for text the others read in
  18–20. For chapter 16 that's 204 s against Kokoro's 133 s. The check rules out
  repeated or added text, so this is pacing: slower speech and longer pauses. That's
  something to judge by ear. Drama 3 has no speed setting (mlx-audio refuses
  `speed` ≠ 1.0).

**VoxCPM2 (Jay Dyer clone).** See step 7.

### The user's own voice, in Dutch

- **Goals:** audiobooks, and podcast-like videos written as text rather than spoken
  (the user finds speaking hard). For publishing, VoxCPM2 (Apache 2.0) has no
  restrictions. Drama 3 may be used commercially below USD 500k revenue a year, but not
  as a hosted service. Its licence also forbids removing the watermark or provenance
  signal it may embed in its output.
- **Recording:** MacBook Pro Microphone via ffmpeg (`-f avfoundation -i ":0"`, mono
  48 kHz), with the user reading a short Dutch passage.
- **Take 1:** 27.5 s, stopped with Ctrl-C, which ffmpeg handles cleanly. The input level
  was too high: 3,475 samples at full scale in 166 short runs, spread over 12 of the 21
  speech seconds. The noise floor was −47 dBFS. Whisper also heard a few words that
  differed from the text. The user re-recorded.
- **Take 2:** input volume lowered in System Settings. The file is 23.4 s rather than 25,
  because ffmpeg needed a moment to open the microphone, and it stops mid-way through the
  third sentence. No clipping, peak −11 dBFS, noise floor −58 dBFS.
- **Reference:** the first two sentences, 1.45–20.05 s (18.60 s), with a 50 ms fade-out,
  peak scaled to −6 dBFS: `out/pilot/me/me_nl_ref.wav`. Whisper's unprompted transcript
  differs only in "binnenvoor" and "luiden", which sound the same as "binnenvoer" and
  "luidden". Prompted with the intended text, it reproduces the text exactly, so that text
  is the transcript.
- **Dutch test text:** `out/pilot/me/nl_test.txt`, written for this pilot. It has two parts:
  a stretch of novel narration and a podcast-style monologue. Project Gutenberg refused
  automated requests (HTTP 503). Dutch Wikisource has *Max Havelaar*, but only in the
  1860 spelling ("hy", "zynen"), which would test the old spelling rather than the voice.

Results:

| Run | Text | Audio | WER | 3+ word errors | Clone similarity | Voice consistency (mean / min) | Words/min |
|---|---|---|---|---|---|---|---|
| VoxCPM2 | Dutch test (title, novel, podcast) | 1.6 min | 2.17% | 0 | 0.774 | 0.902 / 0.806 | 144 |
| Drama 3 | Dutch test | 2.1 min | 2.17% | 0 | 0.799 | 0.898 / 0.786 | 106 |
| VoxCPM2 | 1 Clement title, greeting, chapter 1 (English) | 2.3 min | 1.70% | 0 | 0.756 | 0.900 / 0.793 | 129 |

- **Both engines speak Dutch.** For Drama 3 this wasn't documented (its 83 languages
  aren't listed). Almost all of the Dutch "errors" are writing differences, not speech
  errors: "één" → "1", "twintig" → "20", "eruitzag" → "eruit zag".
- **One real slip:** Drama 3 didn't say the one-word heading "Podcast." (both recognisers
  agree). It's below the 3-word threshold, so the check doesn't flag it. Very short
  lines are a known weak spot for cloning TTS, which matters for chapter headings.
- **The pace comes from the reference.** The user read the reference slowly (30 words in
  18.6 s, about 97 wpm). Drama 3 copies that closely (106 wpm); VoxCPM2 less so (144 wpm,
  129 in English). For a livelier podcast pace, record the reference at that pace.
- **English from a Dutch reference works.** VoxCPM2 read the English sample in the user's
  voice (1.70% WER). Whether it carries a Dutch accent is for listening.
- **Speed:** VoxCPM2 1.5–1.7x realtime. Drama 3's timing for this run is unusable. Its
  last section took 231 s for 67 s of audio because the checks were running on the GPU
  at the same time (its previous section ran at 1.7x).

## 8. Incidents

- **The scratch directory became unavailable mid-run.** The section WAVs, logs, reference
  clips and source text were all in the session's temporary scratch folder. Drama 3 was
  stopped after 12 of 19 sections, and everything was copied to `out/pilot/` (hashes
  re-checked). Drama 3 then resumed: `pilot_render.py` skips finished sections. Before
  resuming, the last finished section was checked to be complete (106.84 s, matching its
  timings line). The resumed run reloaded the model, which isn't counted in the
  per-section times.
- **GPU sharing.** Some small jobs ran while renders were in progress: the voice-pick
  script, the Dutch recordings' transcription, and the check re-runs. The Drama 3 timing
  for the Dutch test is the only one clearly affected (step 7). The 1 Clement timings come
  from runs with the GPU to themselves, except for a few seconds of Whisper here and there.

## 9. Conclusions

- **For English audiobooks in a stock voice:** stay with Kokoro, or switch to Phonon if a
  Phonon voice sounds better. Both are fast, accurate and small. Phonon's voice varies
  more, so listen to a long section before choosing it.
- **For audiobooks in a cloned voice** (your own, or one you have permission for): use
  VoxCPM2. It's accurate, steady, about 35 minutes for a 66-minute book, Apache 2.0, and
  it speaks Dutch.
- **Drama 3** is the most accurate and the closest clone. Whether that's worth 29 GB, a
  slower render and a slower reading pace is for listening to decide.
- **For podcast-style videos in your own voice:** use VoxCPM2 (or Drama 3) with a
  reference recorded at the pace and tone you want. A calm read-aloud reference gives a
  calm read-aloud clone.
- **Before a full book:** short headings ("Podcast.", "Chapter 1.") deserve a check. If an
  engine drops them, render them with a little more context or a fixed pre-rendered clip.
